# Court Booking Bot 🎾🟦⚽🏐

Telegram-бот для бронирования кортов и полей: **большой теннис, падел, футбол, волейбол**.
Две стороны: **игрок** (бронирует) и **владелец площадки** (управляет кортами).

## Возможности

**Игрок** (`/start`)
- Выбор вида спорта (теннис / падел / футбол / волейбол)
- Список площадок с кортами по выбранному спорту
- Календарь на 7 дней вперёд, слоты по 1 часу (08:00–22:00)
- Бронирование свободного слота в один тап
- **Защита от двойного бронирования** на уровне БД (`UNIQUE (court_id, start_iso)`)
- «Мои брони» — просмотр и отмена своих будущих броней
- Прошедшие по времени слоты не бронируются

**Владелец** (`/owner`) — сделано под скорость:
- Создание площадки одним сообщением (`Название, Город, Адрес`)
- **Добавление корта в один тап** по шаблону спорта (покрытие и цена
  подставляются по умолчанию, правятся позже)
- Расписание свободных слотов **генерится автоматически** из кортов —
  владельцу не нужно заводить каждый слот
- Правка цены/названия, дубликат корта одной кнопкой
- **Блокировка часов** (турнир/ремонт) одним тапом по сетке часов;
  заблокированный час исчезает у игроков, забронированный — не блокируется
- Просмотр предстоящих броней по площадке
- Изоляция доступа: владелец управляет только своими площадками

## Стек

- **grammY** — Telegram Bot API
- **better-sqlite3** — хранилище (синхронное, транзакционное)
- **TypeScript** на Node.js

Слой данных (`src/db.ts`) не зависит от Telegram, поэтому логика тестируется отдельно.

## Запуск

```bash
cd booking-bot
npm install

# 1. Получи токен у @BotFather в Telegram
cp .env.example .env        # и впиши BOT_TOKEN

# 2. (необязательно) проверить логику без Telegram
npm run smoke

# 3. Запуск бота
npm run dev                 # режим разработки (tsx watch)
# или
npm run build && npm start  # продакшн-сборка
```

При первом запуске база автоматически наполняется тестовыми площадками
(`src/seed.ts`). Перезалить данные: `npm run seed -- --force`.

После запуска открой своего бота в Telegram и отправь `/start`.

## Команды бота

| Команда | Действие |
|---|---|
| `/start` | Выбрать спорт и забронировать слот |
| `/mybookings` | Мои брони и отмена |
| `/owner` | Кабинет владельца площадки |
| `/help` | Справка |

> Один и тот же бот обслуживает обе роли: владельцем становится любой,
> кто открыл `/owner` и создал площадку; управлять можно только своими.

## Структура

```
src/
  domain.ts   — типы, виды спорта, шаблоны кортов, работа со слотами/датами
  db.ts       — SQLite: схема, площадки, корты, брони и блокировки слотов
  seed.ts     — демо-данные (3 площадки, 9 кортов)
  bot.ts      — сторона игрока (выбор → бронь → «мои брони»)
  owner.ts    — сторона владельца (площадки, корты, цены, блокировки)
  index.ts    — точка входа (long polling)
  smoke.ts    — дымовой тест логики без Telegram
```

## Модель занятости слотов

Брони игроков и блокировки владельца лежат в одной таблице с полем `kind`
(`booking` / `block`). Констрейнт `UNIQUE (court_id, start_iso)` одним
правилом гарантирует, что слот нельзя ни забронировать дважды, ни
заблокировать уже забронированный (и наоборот). Свободные слоты нигде не
хранятся — они вычисляются как «часы работы минус занятые».
